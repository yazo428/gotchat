# アプリ使用の流れ
## (ホスト)イベントの作成
イベントのホストが、イベントを作成する
- 必要な情報
  - イベント名
  - 日程の候補
    - 日付
    - 時間
      - 単位は30分単位
  - 回答の締切
  - イベントの説明・メモ

入力後、イベントidとそのurlを発行

## (参加者)日程の入力
- 候補日(と、リスト？)がカレンダーで見やすく表示される
- それぞれの日程について、○/△/×で参加できるかを回答する
- 名前、コメントの入力する？

## 日程の確定
- 回答の締切 or ホストが締め切ったタイミングで回答はできなくなる

## 不足している主な観点

1. ホストの認証・再アクセス

- ホストはどうやって自分のイベントを再管理するか？（URLだけ？ログイン不要？）
- ホストのみができる操作（締め切り・編集・削除）をどう保護するか

2. 結果・集計の表示

- 回答結果をホスト/参加者はどう見るか（表形式？カレンダー？）
- 一番参加可能人数が多い日程の自動推薦はあるか
- 参加者同士の回答は互いに見えるか

3. 日程の「確定」後のフロー

- ホストが最終日程を決定する操作が未定義
- 確定後に参加者への通知はあるか（メール等）

4. 参加者の再編集

- 回答済みの参加者が回答を変更できるか
- 参加者の識別方法（名前だけ？重複した名前はどう扱う？）

5. タイムゾーン

- 参加者が複数地域にいる場合の時間帯の扱い

6. エッジケース

- 誰も回答しないまま締め切りを迎えたら？
- 候補日が1つだけの場合は？
- 締め切り延長はできるか？

7. URL・データの有効期限

- イベントURLはいつまで有効か
- データの保存期間
